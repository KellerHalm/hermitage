### Исправление 4 — Nonce-based CSP вместо `'unsafe-inline'`

**Подход:** генерировать per-request nonce в Next.js middleware и использовать его в `script-src`. Для `style-src` оставлю `'unsafe-inline'` — Next.js/Tailwind генерируют inline-стили, к которым nonce автоматически не применяется; их блокировка сломает вёрстку. Главная XSS-защита (отказ от `'unsafe-inline'` для скриптов) при этом работает.

**Шаги:**
1. **Создать `NextProject/middleware.ts`** — генерирует `nonce` (base64 от UUID), формирует CSP-строку с `script-src 'self' 'nonce-...'`, кладёт nonce в заголовок `x-nonce` и выставляет `Content-Security-Policy`.
2. **`NextProject/app/layout.tsx`** — сделать функцию `RootLayout` асинхронной, читать nonce через `headers()` из `next/headers` и передать его в `<body nonce={nonce}>`. Next.js автоматически применит nonce к своим bootstrap inline-скриптам.
3. **`nginx/nginx.conf`** (строка 74) — **удалить** строку `add_header Content-Security-Policy ...`, чтобы CSP шёл только из Next.js (иначе два CSP-заголовка конфликтуют; остальные security headers в nginx остаются).

### Исправление 5 — Ограничить CORS для запросов без `Origin`

**Подход:** строгий режим только в production. В development оставить пропуск запросов без `Origin` (нужно для curl, инструментов, возможных SSR-вызовов).

`hermitage-backend/src/app.js` (строки 36-47) — переписать origin-проверку:
```js
origin: (origin, callback) => {
  const allowed = config.clientOrigins.includes(origin);
  if (config.nodeEnv === 'development' && !origin) {
    return callback(null, true); // dev: пропускаем curl/инструменты
  }
  if (!origin || !allowed) {
    return callback(new Error('Not allowed by CORS'));
  }
  callback(null, true);
},
```
