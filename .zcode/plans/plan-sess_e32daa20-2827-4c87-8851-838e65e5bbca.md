# Поэтапный план: исправление нюансов + реализация пунктов ТЗ

Решения подтверждены: серверные фильтры · `oldPrice` для скидок · без отзывов · полный CRUD пользователей.

Работа разбита на **7 этапов** (backend → frontend, каждый этап логически независим). В конце — миграция и проверка сборки.

## Этап 1 — Backend: скидки (`oldPrice`) + nested-категории в фильтре

**Schema** (`hermitage-backend/prisma/schema.prisma`):
- Product: добавить `oldPrice Decimal? @db.Decimal(10, 2)`

**Миграция** (новая папка `prisma/migrations/20260724000000_product_oldprice/migration.sql`):
- `ALTER TABLE "Product" ADD COLUMN IF NOT EXISTS "oldPrice" DECIMAL(10,2);`

**`productService.js`**:
- `buildProductPayload` (≈стр. 25-42): добавить `oldPrice: data.oldPrice ? parseFloat(...) : null`
- `updateProduct` (≈стр. 193-212): `if (data.oldPrice !== undefined) updateData.oldPrice = data.oldPrice ? parseFloat(data.oldPrice) : null`
- `getAllProducts` (≈стр. 100-140): 
  - categoryId/brandId/color/material/country → multi-value (`{ in: [...] }`), чтобы поддержать массивы фильтров
  - **nested-категории**: при фильтре по родительской категории собрать все descendant-ids (через существующий `findMany({ where: { parentId } })`) и использовать `where.categoryId = { in: [parentId, ...childIds] }`
  - добавить фильтр `onlyDiscount` (`?isSale` уже есть) — оставить как есть
  - новый `sort: 'discount'` → `orderBy: { oldPrice: 'desc' }`

**`seed.js`** (≈стр. 45-259): добавить `oldPrice` части товаров (где `isSale: true`) + создать несколько **nested** категорий (родитель «Спальня» → дочерние «Кровати», «Шкафы», «Комоды»; и т.д. по структуре ТЗ 2.1B), привязав часть товаров к дочерним. Так nesting станет реальным, а не только схемой.
